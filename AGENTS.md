# SAC Nexus Agent Instructions

## Project Overview

- This is a polyglot monorepo starting with `apps/web`.
- Use `pnpm` for all JavaScript package operations.
- Use Turborepo for monorepo task orchestration.
- Keep technical docs, code, routes, filenames, commits, and PRs in English.
- Keep user-facing UI labels and copy in Brazilian Portuguese.

## Package Management

- Use `pnpm install` to install dependencies.
- Use `pnpm add` and `pnpm add -D` to add dependencies.
- Use `pnpm dlx` for one-off CLIs.
- Use `pnpm dlx shadcn@latest` for shadcn operations.
- Do not manually edit `package.json` to add dependencies or pin versions when pnpm can do it.

## Monorepo Tasks

- Root scripts must delegate to `turbo run <task>`.
- Prefer package-level scripts over root task logic.
- Use native tooling inside each app/service and let Turbo orchestrate.

## Git Workflow

- Feature branches target `staging` through pull requests.
- Production promotion happens through pull requests from `staging` to `main`.
- Use squash merge for protected branches.
- Keep `staging` and `main` linear and protected.
- Delete merged feature branches.

## Documentation

- Initiative PRDs live in `docs/initiatives/prds`.
- Initiative execution plans live in `docs/initiatives/tasks`.
- Initiative source handoffs live in `docs/initiatives/sources`.
- Use `sac-nexus-initiative-workflow` when creating, reviewing, updating, or
  executing initiative PRDs and plans.
- Use `sac-nexus-architecture` for app, module, package, documentation, and
  skill-boundary decisions.
- Use `sac-nexus-preflight-review` before a branch moves to review, QA, staging,
  production, commit, push, or PR creation.
- Use `sac-nexus-pr-review-triage` for feature PR feedback targeting `staging`.
- Use `sac-nexus-release-workflow` for production promotion, deployment
  readiness, or rollback.
- Global backlog lives in `docs/TODO.md`.
- Durable frontend docs live in `docs/web`.
- Durable IDP docs live in `docs/idp`.
- AI-DLC artifacts generated by the OpenCode AI-DLC skill follow the vendored AI-DLC v2 artifact convention.
- Project-authored skills use the `sac-nexus-` prefix. Keep downloaded skills
  upstream-owned and encode local policy in project wrapper skills.
- For every code, behavior, workflow, architecture, or convention change, explicitly check whether README, AGENTS, PRD/task docs, durable docs, or backlog updates are needed.
- If documentation does not need updates, be prepared to state why during review or handoff.

## AI-DLC Workflow

- When the user starts a request with `Using AI-DLC`, `AI-DLC`, or `AIDLC`, use the OpenCode skill in `.agents/skills/aidlc/SKILL.md`.
- AWS AI-DLC v2 is vendored under `.aidlc/aidlc-v2/` and adapted for OpenCode by `.agents/skills/aidlc/SKILL.md`.
- Project-specific rules in this file remain authoritative when they are more specific than generic AI-DLC guidance.

## Safety

- Do not store secrets in frontend env vars.
- Do not store auth tokens in `localStorage`.
- Never read, grep, print, summarize, or modify real `.env` files such as `apps/idp/.env`; use `.env.example` files only.
- Do not modify unrelated services or modules unless explicitly requested.

## Review guidelines

- Prioritize correctness, security, privacy, user-visible regressions, and missing tests.
- Flag accidental logs of credentials, PII, tokens, or other sensitive values.
- Verify that loading and disabled states prevent duplicate actions without layout shift.
- Verify that frontend changes remain accessible through keyboard and screen-reader workflows.
- Treat broken CI, skipped verification, and missing regression coverage as review risks.
- Treat review comments as hypotheses and classify them with evidence before
  changing code or resolving threads.
- Feature PRs target `staging` and include
  `@codex review in Brazilian Portuguese` once. Production promotion PRs from
  `staging` to `main` omit the Codex review trigger.
