# SAC Nexus Web

React single-page application for SAC Nexus.

This app contains the browser frontend used by Brazilian users. Technical files, routes, and documentation are written in English. User-facing labels and copy must be written in Brazilian Portuguese.

## Stack

- **Vite** for development and build tooling.
- **React** for UI.
- **TypeScript** with strict compiler settings.
- **TanStack Router** for file-based client routing.
- **TanStack Query** for server state and cache.
- **ky** for HTTP requests.
- **zod** for environment validation and future runtime contracts.
- **React Hook Form** with Zod for business forms.
- **Tailwind CSS v4** for styling.
- **shadcn/ui** with Base UI primitives for shared UI components.
- **lucide-react** for icons.
- **MapLibre GL JS** with OpenStreetMap tiles for operational and
  establishment-location maps.
- **Biome** for formatting, linting, import organization, and Tailwind class sorting.
- **Vitest**, **React Testing Library**, **MSW**, and **Playwright** for tests.

## Requirements

Run commands from the repository root unless explicitly stated otherwise.

- Node.js `26.0.0` or newer stable versions when intentionally upgraded.
- pnpm managed by Corepack.

Install dependencies from the repository root:

```bash
pnpm install
```

## Environment

Copy the example environment file when local overrides are needed:

```bash
cp apps/web/.env.example apps/web/.env
```

Current public frontend variables:

```env
VITE_API_URL=/api
VITE_AUTH_URL=/api/auth
VITE_APP_NAME="SAC Nexus"
VITE_APP_ENV=local
VITE_ENABLE_MSW=false
VITE_GOOGLE_MAPS_API_KEY=
```

Environment variables are validated in `src/modules/shared/config/env.ts`.

`VITE_GOOGLE_MAPS_API_KEY` is optional and only enables Google Street View imagery in the operational map.

Do not access `import.meta.env` directly outside this file.

The contributor establishment form uses an explicit public Nominatim lookup
only after the user confirms a complete address. It does not use autocomplete,
and lookup failures fall back to manual pin placement. This direct integration
is presentation-only; production geocoding must use an approved backend
provider boundary.

## Development

Start the web dev server:

```bash
pnpm --filter web dev
```

The app runs at `http://localhost:5173`.

The Vite dev server proxies `/api` to the configured local backend target in `vite.config.ts`.

## Git Hooks

Git hooks are configured at the repository root with Lefthook.

Husky is not used.

After the project is inside a Git repository, install hooks from the root:

```bash
pnpm lefthook install
```

## Commands

- Start dev server: `pnpm --filter web dev`
- Build: `pnpm --filter web build`
- Preview production build: `pnpm --filter web preview`
- Check formatting and lint rules: `pnpm --filter web check`
- Format and apply Biome fixes: `pnpm --filter web format`

## Architecture Rules

- Main application code lives under `src/modules/*`.
- `src/modules/shared/*` can be imported directly.
- Business modules expose public APIs through `index.ts`.
- Business modules should not deep-import from other business modules.
- shadcn/ui components live in `src/modules/shared/components/ui`.
- Generated files such as `src/routeTree.gen.ts` must not be manually edited.

## Routing

Routes are file-based and live in `src/routes`.

The route tree is generated by TanStack Router. It is regenerated before `build` and `typecheck`.

Use route context for shared route dependencies, such as the TanStack Query Client.

## UI And Styling

Use shared UI components from `src/modules/shared/components/ui` before creating custom markup.

Prefer semantic Tailwind tokens such as:

- `bg-background`
- `text-foreground`
- `text-muted-foreground`
- `border-border`

Use `cn()` from `src/modules/shared/lib/utils.ts` for conditional classes.

## Testing

Tests are centralized under `tests`.

- Unit/component tests: `tests/unit`
- E2E tests: `tests/e2e`
- MSW setup: `tests/msw` and `tests/setup.ts`

Run tests with:

```bash
pnpm --filter web test
pnpm --filter web test:e2e
```

## Journey Recordings

Guided journey recordings are presentation artifacts, not regression tests.
They use Playwright as a browser driver while adding a visible cursor,
highlights, captions, and deliberate presentation timing.

Start the development server, then record the Risco 1 journey:

```bash
pnpm --filter web dev --host 127.0.0.1
pnpm --filter web record:risk-one
pnpm --filter web record:risk-two:no-inspection
pnpm --filter web record:risk-two:with-inspection
pnpm --filter web record:risk-two:requirement
pnpm --filter web record:journeys
```

Generated videos, reports, and documents are written under
`artifacts/journey-recordings` and are ignored by Git. When `ffmpeg` is
available, the recorder produces a shareable MP4; otherwise it preserves the
original Playwright WebM recording.

On macOS, install the optional MP4 converter with:

```bash
brew install ffmpeg
```
